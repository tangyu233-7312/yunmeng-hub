## 直接用：下载装好的版本

不想装 Python、不想配环境，**只想要能用的界面**，来这里：

> [**→ 云梦枢 Releases（最新为 v0.4.0）**](https://github.com/tangyu233-7312/yunmeng-hub/releases)
>
> Release 里**两种形态，二选一**（同一个后端、同一份数据格式、功能一致）：
>
> | 文件 | 形态 | 怎么用 |
> |---|---|---|
> | `YunMengHub-Web-0.4.0.zip`（约 164 MB） | **Web 版**，免安装 | 解压到任意目录 → 双击「启动云梦枢.cmd」→ 浏览器自动打开控制台 |
> | `YunMengHub-Setup-0.4.0.exe`（约 235 MB） | **安装版** | 双击 → 按向导选目录 → 从开始菜单或桌面图标打开 |
>
> 只出 **Windows x64**；macOS / Linux 未做。
>
> 两者都没做代码签名，首次运行会被 SmartScreen 提示"未知发布者"——属预期行为，
> 点「更多信息 → 仍要运行」即可。
>
> 每个 Release 页面附有 SHA256，下载后可用
> `certutil -hashfile "YunMengHub-Web-0.4.0.zip" SHA256` 核对。
> （本地构建出来的文件名是中文的 `云梦枢 Web 0.4.0.zip` / `云梦枢 Setup 0.4.0.exe`，
> 上传 GitHub 后中文与空格会被清洗成 ASCII，两者内容完全相同。）

## Web 版（绿色免安装）

它和安装版是**同一个 `backend.exe`、同一份 `web/` 前端**，区别只在"打开方式"：
安装版由 Electron 开一个独立窗口，Web 版由启动器起后端、用**你的浏览器**打开控制台。

```
云梦枢 Web 0.4.0\
  ├─ 启动云梦枢.cmd       ← 双击这个
  ├─ start.ps1            ← 真正的逻辑：预检 → 选端口 → 起后端 → 开浏览器
  ├─ 使用说明.txt
  └─ backend\
       ├─ backend.exe
       └─ _internal\
```

**启动前会做一次环境预检**，并区分两类结论：

| 类别 | 检查什么 | 表现 |
|---|---|---|
| **阻断**（继续下去必然失败） | 解压是否完整（缺 `backend.exe` / `_internal` / 组件被安全软件清掉）、系统架构是否 x64、PowerShell 版本、数据目录能否写入、指定端口是否被占 | 红字列出原因并**不启动**，避免"窗口一闪就没" |
| **提醒**（能跑，但要知悉） | 是否首次运行、端口 8000 被占（会自动换）、是否已有实例在跑（同数据目录并发写会锁）、磁盘剩余空间 | 黄字列出，然后照常启动 |

启动后还会核对 `/health` 的**组件状态**：接口返回 200 不代表一切正常 ——
若数据库或向量库降级，窗口里会明确写出是哪个组件，而不是让用户以为已经就绪。

```powershell
# 手动启动（排查问题用，报错会停住不走）
powershell -NoProfile -ExecutionPolicy Bypass -File start.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File start.ps1 -Port 8010 -DataDir "D:\云梦枢数据"
```

**数据位置**与安装版相同（默认 `%APPDATA%\云梦枢`），所以**两者可以换着用、看同一份数据**；
但**不要同时开两个**（SQLite 同一时刻只允许一个写事务）。

构建这个压缩包：

```powershell
# 复用已有的打包后端（desktop/dist/backend），产物在 release\云梦枢 Web <版本>.zip
powershell -NoProfile -ExecutionPolicy Bypass -File desktop\scripts\build_web_bundle.ps1 -Verify

# 先重建后端再打包
powershell -NoProfile -ExecutionPolicy Bypass -File desktop\scripts\build_web_bundle.ps1 -Rebuild -Verify
```

`-Verify` 会**解压到临时目录、真起一次服务**，探 `/health`（组件必须全 ok）与 `/console`，
不通过就报错 —— 不做这一步，"打包成功"只是一句话。

## 自己从源码构建

见 **[`desktop/README.md`](../desktop/README.md)**（§0 首次打开会发生什么 / §7 打包后端 / §8 安装包）。
三个阶段的用法各一句话：

```powershell
# ① 开发态：仓库里直接跑（需要本机 Python；数据库默认 sqlite，不需要 MySQL）
cd desktop
npm install
npm start

# ② 打包后端：之后用户机**不需要 Python**
powershell -File scripts\build_backend.ps1

# ③ 出 Windows 安装包 → 仓库根 release\（文件名形如 `云梦枢 Setup 0.4.0.exe`）
npm run build:installer
```

`desktop/` 只是**壳**：它选一个空闲端口、拉起后端（**优先用打包好的 `backend.exe`**，
找不到才退回本机 Python）、轮询 `/health` 就绪后加载控制台，退出时把后端子进程整棵树收掉。
**后端契约与 `web/` 一行未改**，所以上面那套验收方式照旧有效。

装出来的那份第一次打开会进**首次设置**页，默认「存储方式 = 本机文件（SQLite）」：
**什么都不用填**，点「保存并开始」即可用（表由后端建、密钥由后端生成）。
想用 MySQL 就在那一屏切成 MySQL 再填连接信息；保存时它**真的把后端起起来逐项自检**
（数据库 / 向量库），通过才进控制台。
配置写在**用户数据目录**（Windows：`%APPDATA%\云梦枢\config\.env`，
自动生成的密钥在同目录的 `.secrets.env`），
**不在安装目录里** —— 卸载重装不丢；卸载也**不删**用户数据。

> ⚠️ 诚实边界（三条，都不打算含糊）：
> ① 默认存储是本机文件，**不需要额外安装任何东西**；但如果你要选 MySQL，
>    那就得自备一个 MySQL 8 实例（应用不附带数据库服务器）；
> ② 安装包**没有代码签名**，首次运行会被 SmartScreen 提示"未知发布者"
>    —— 这需要用户自己的代码签名证书，不是缺陷；
> ③ 安装包只出了 **Windows x64**（NSIS），macOS / Linux 未做。
>
> 自动验收（装 → 首启向导 → 控制台 → 卸载后数据还在）：
> `powershell -File desktop\scripts\verify_installer.ps1`（详见 [`desktop/README.md`](../desktop/README.md) §8）。
