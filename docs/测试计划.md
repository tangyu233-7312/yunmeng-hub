## 清理与验证原则

- 删除简单 DTO/ORM 字段回显、源码字符串、标题/默认常量和重复正常值；每条删除须有理由或替代行为。
- 随机公平性/固定语料消融仍可通过 benchmark 命令运行，不混进产品回归 passed。
- 迁移、秘密存储、超时、流式输出边界不能因为没有 HTTP client 就被删掉。
- 无 DB 测试移入 tests/unit，其余明确区分 integration/acceptance/live；不以 client 字符串决定价值。数量由审查决定，不设删减指标。
- 前端 boot 保留 VM 行为测试；布局、浏览器富文本、Electron IPC 全链路及安装卸载仍需真实浏览器/桌面验收，不能声称自动覆盖。
- 验证顺序：基线→逐层收集和执行→全量→Ruff/文档/SQL/零配置→选定故障注入。注入样本通过不能推断全项目 mutation 分数。
- 参数化一行仍是一次独立执行。同时报告函数数、收集数、skip 与层级，避免用缩短函数数冒充覆盖提升。

桌面逐项理由见 [桌面审查明细](desktop-test-review.tsv)。删除配置 getter、源码接线猜测与产物存在断言；保留实际配置回环、进程清理和网络就绪边界。设置页只保留少量脚本事件场景。
